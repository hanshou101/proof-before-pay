## 1. 風格預設

- 預設：`fintech-precise`（`design/tokens.css`），`<html data-theme="fintech-precise">`。2026-11-01 照樣板重調成宿主 2025 年的產品語言：中性底、近黑字、主操作是黑色膠囊、藍只給連結與焦點。
- 為什麼：賽題是「AI agent 動錢」，評委 6 位是 PayPal 的開發者關係與產品；目標用戶是替工作室付款的營運負責人。要的氣質是「可以放心把錢交給它」，出處是宿主自己的設計語言（尺子見第 2 節）。
- 顏色：`--accent` 近黑 `#0A0E17`（主操作的實心膠囊），`--accent-text` 藍 `#1A56DB`（連結與焦點）；`--bg #EDF1F7`、`--surface #FFFFFF`、`--surface-2 #F3F5F9`、`--border #DCE1E9`。`python3 scripts/check_tokens.py` →「对比度全部达标」。
- 顏色紀律：實心黑色膠囊每屏只一顆，給當下最重要的那一個操作（運行前「Run Friday payouts」，運行後「Review 2 held」）。`--success` 只給 proven，`--warning` 只給 held（狀態片與主句第二行），`--danger` 只給 blocked / fraud；藍只給連結與焦點。宿主現行識別沒有琥珀色，held 仍用琥珀，理由見 `design/sample/README.md` §2。
- 字體：Plus Jakarta Sans 400–800（介面與數字，等寬數字用 `tnum`）、IBM Plex Mono 400 / 500（電郵、雜湊、帳本），woff2 放 `design/fonts/`，`@font-face` 本地載入。用到的每個字重都要有字面：`.dialog-amount` 要的 Mono 600 還沒補（§6 D1-3）。
- 圖標：Lucide（`lucide-react`），1.5px 線寬，不用 emoji。

### 4.3 字號（樣板的階梯，6 級）

12px（大寫小標、欄頭、帳本雜湊）｜14px（資料與次要資訊：行內說明、發票號、副行、狀態片、時間線、按鈕）｜16px（正文、名字、金額、電郵）｜20px（面板標題）｜28px（總額）｜40px（主句）。全部用 `--fs-xs / --fs-sm / --fs-md / --fs-lg / --fs-xl / --fs-2xl`，在 `styles.css` 頂部宣告一次。

和 AGENTS.md §4.6「一屏最多 4 級」不同：尺子要一句最大的主句和面板標題，樣板用 6 級，改成機器查得了的規矩——字號只來自這條階梯（`apps/web/scripts/scan-tokens.mjs` 查裸值，`scripts/measure-ui.mjs` 查渲染出來的字號）。這是倉庫內規與尺子衝突，記一筆交用戶定；Dinner Tower 是同一個取捨，用戶 10-31 認可過那一次。

**正文 = 成句的文字，一律 16px**（AGENTS.md §4.6「正文 ≥ 16px」）。目前是正文的元素：AI 風險說明 `.note-text`、面板說明句 `.detail-text`、「Why it's held」各條 `.why-item`、出錯橫幅 `.run-banner-text`、Verify payee 的指示 `.verify-instruction`。新加成句的文字照此辦，並加進 `scripts/measure-ui.mjs` 的 `BODY` 清單。樣板裡它們還是 14px（D1-1，樣板弱點 1）。

按鈕一級：膠囊按鈕一律 14px/700；頁頭的高 40px，卡片、抽屜、對話框、橫幅裡的用 `btn--sm`（36px），詳情面板三顆按鈕才放得進一行。10-22 的 D1 裁定是頁頭 16px、其餘 14px，樣板照宿主的膠囊按鈕改成一級。

### 4.4 詳情面板（選中 Ana：記憶點那一格）

由上而下，內距 `--sp-5`：

1. 狀態片「Held」＋標題「Payment details changed by email」（20px/800）同一行；下一行副行「Ana Ribeiro · Studio North · INV-2207 · $2,400.00」（14px muted）。
2. 「Payee check」放在一口 `--surface-2` 的井裡：兩組，每組先一行小標（「On file · Verified Mar 2 · video call」前置綠勾，「Requested · By email · Nov 4 · not verified」前置紅叉），下一行是電郵（mono 16px）。`0` 用 danger 色淡底高亮。高亮不佔寬度：`0` 的盒子寬 = 一格等寬字 ±0.5px，淡底用 box-shadow 往外擴，不用 padding（D1-4，還沒做）。
3. 「AI risk note」區：前置 `sparkles` 圖標（muted）與 12px 標記「AI」，正文 16px、合計 ≤ 140 字元、1280×720 下最多 3 行（SPEC §6.6.2 第 4 步同步限長）：「The sender's domain imitates studionorth.example — a zero replaces the letter o. It urges same-day payment and tells an AI to approve it.」（137 字元；文字由模型生成，這裡是長度與語氣的樣板。主控 D1 實測：16px、寬 374px 下 3 行。）
4. 「Why it's held」區（閘的事實，確定性文案；標題照抄「Why it's held」，blocked 時「Why it's blocked」）：「Payee differs from the verified payee」·「Unverified change request (Nov 4)」，每條前置 `circle-alert`。
5. 操作列（底部，上方 1px 分隔線）：「Verify by phone」（描邊膠囊，`phone` 圖標）＋「Reject as fraud」（danger 描邊）。「Approve」顯示為停用，懸停提示「Verify the payee first」。三顆都是 `btn--sm`，一行放下。內文最後一行到分隔線 ≥ 16px（樣板弱點 2；`screenshots.ts` 與 `measure-ui.mjs` 都量）。
6. 頁腳：「Proof log · event #37 · 9c41…e2a7」（12px mono muted）。

選中 Proven 行時，面板換成證明包摘要（時間線：Invoice read → Owed → Payee → Policy → Sent to PayPal → Proven，每步一行帶時間），底部「Open proof bundle」。「Invoice read」用郵件的收到時間；同一天的其餘步驟顯示到秒（`HH:MM:SS`），不然真實運行裡六步都是同一分鐘（D1-11）。時間線樣式見 D1-8。

### 4.5 狀態

主句跟著狀態換（`RunHero.tsx`，句子由帳本算出）：空「Nothing is paid until it's proven.」；讀信「Reading the inbox. Nothing is paid until it's proven.」；運行中「Checking 5 of 8 invoices. Nothing is paid until it's proven.」（樣板裡這一句折成三行，要改短到 ≤ 2 行：樣板弱點 4）；完成「4 paid with proof.」「2 need your review.」（沒有 held 時第二句是「Nothing needs you.」）；出錯「The run stopped. Nothing more is paid until it is fixed.」

- **載入中**（連上伺服器、快照還沒到）：主句、總額卡與清單 8 行用同尺寸的 `--surface-2` 骨架（`HeroSkeleton.tsx`），不出現空白頁（D1-12）。
- **空（還沒運行）**：KPI 金額顯示「—」；清單列出 8 張發票，印章全是待查，狀態「Ready」；詳情面板：標題「Nothing is paid until it's proven.」（和主句同一句，照樣板做時改掉其一）＋說明「9 documents from 7 freelancers arrived this week.」＋「What the gate checks」四行 ＋ 次按鈕「Run Friday payouts」（D1 裁定：頁頭已有同一個 accent 主按鈕，一屏只留一個 accent，面板裡用次按鈕）。不允許大塊空白：卡片內最大空白 ≤ 120px（D1-2）。
- **運行中**：每行印章從左到右依次點亮（每枚 150–250ms 過渡）；狀態片依次變化；頁頭主按鈕變「Running… 5 / 8」（停用）；KPI 金額在該行定案時更新。
- **完成**：如 4.1；主按鈕變「Review 2 held」。
- **出錯**：運行清單頂部一條 danger 淡底橫幅，一句人話 ＋「Retry」：PayPal 連不上時「Couldn't reach the PayPal sandbox. Nothing was sent. Check PAYPAL_CLIENT_ID in .env, then retry.」；模型沒回時「The AI model didn't respond. Nothing was sent. Retry, or set a different LLM_MODEL.」原始錯誤在開發者開關後面。

### 4.7 其他屏幕（過衛生線即可，同一套變量與組件）

- 「Proof bundle」抽屜（右側 560px）：時間線 ＋ 每步的證據（原件名與 sha256 前 12 碼、AI 抽取欄位帶「AI」標記、合約 PO 與金額規則、交付驗收人與時間、收款人核驗記錄、三條政策、PayPal batch / item / transaction id、狀態、取回時間、「Verify again」按鈕）＋「Export JSON」。
- 「Verify payee」對話框：on file 與 requested 並排；說明「Call the number on file — not the one in the email」；結果選項「Confirmed by phone」「Not confirmed — likely fraud」；備註欄（自繪輸入框）。
- 「Inbox」：9 封郵件列表 ＋ 原件預覽 ＋ AI 分類標籤（「Invoice」「Payee change request」「Not an invoice」）。
- 「Ledger」：全部歷史，篩選片（自繪）、鏈驗證徽章、匯出。
- 「Comparison」：同一張運行清單，頁頭下方一條 danger 淡底橫幅「Comparison mode — the same agent with no proofs. For demonstration only.」；印章欄顯示不適用，狀態欄顯示 agent 自己的說法。
